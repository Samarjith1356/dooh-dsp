# Programmatic DOOH in ten minutes

## The chain

```
Advertiser -> DSP (us) -> SSP (e.g. VIOOH) -> media owner (e.g. JCDecaux) -> screen
```

A screen plays a loop of ads. When a slot is free, the media owner's player asks its SSP to sell it. The SSP sends a **bid request** to connected DSPs. Each DSP answers with a bid or a no-bid within the time limit (`tmax`, often around 100ms; we answer in under 1ms). The highest bid wins. The SSP then tells the winner through the **win notice** (`nurl`). When the ad actually plays, the SSP fires the **billing notice** (`burl`).

We pay for plays, not for bids or wins. Spend is booked only on the billing notice (see [`contracts/events.md`](../contracts/events.md)).

## Plays and impressions

One play on a busy street is seen by several people. The SSP sends an **impression multiplier** (`imp.qty.multiplier`). For example, 5.2 means this play counts as 5.2 impressions.

Prices are quoted as **CPM**, the cost per 1,000 impressions.

```
cost of one play = CPM x multiplier / 1000
example: EUR 10 CPM x 5 / 1000 = EUR 0.05 per play
```

Reading the multiplier wrong is the most expensive bug in DOOH. Parse it, store it, test it.

## How inventory is sold

- **Open auction:** any connected DSP can bid.
- **Private marketplace (PMP) deal:** invited buyers only, with an agreed floor price and a deal ID in the bid request. Most programmatic DOOH spend runs through PMP deals.
- **Creative approval:** media owners often approve each creative before it can play. A bid that carries an unapproved creative wastes the slot.

## Money in our code

All money is stored as integer **micros**: 1 EUR = 1,000,000 micros. Never use floats for money that is stored or billed. Prices arrive from SSPs as CPM floats. Convert them at the edge and keep integers from there on.

## Glossary

| Term | Meaning |
|---|---|
| Slot / play | One showing of an ad on one screen, usually 5-10 seconds |
| Loop | The repeating sequence of slots a screen plays |
| CPM | Price per 1,000 impressions |
| Impression multiplier | How many people one play counts as (`imp.qty.multiplier`) |
| SSP | Supply-side platform: sells screens' slots in auctions (VIOOH, Broadsign, Hivestack, Vistar, Place Exchange) |
| DSP | Demand-side platform: bids for advertisers. That is us |
| Media owner | Owns the screens (JCDecaux, Bauer Media Outdoor, Global) |
| OpenRTB 2.6 | The bidding protocol. Version 2.6 has proper DOOH fields |
| `tmax` | The SSP's time limit for a bid response |
| `nurl` / `burl` / `lurl` | Win, billing and loss notice URLs we put in our bid. The SSP calls them |
| `${AUCTION_PRICE}` | Macro the SSP replaces with the clearing price when it calls our notice URL |
| Clearing price | The price we actually pay, which can be below our bid |
| Floor | The minimum price the seller accepts |
| Deal ID / PMP | A private marketplace deal and its identifier |
| Seat | Our buyer account on an SSP |
| `schain` / sellers.json | The supply-chain record of who is selling the impression |
| Venue type | The kind of place a screen is in (roadside, transit, retail...) |
| Daypart | Time-of-day and day-of-week targeting |
| Geofence | An area a campaign may or may not bid in |
| Pacing | Spreading a budget over the campaign's dates |
| Creative spec | The size, format and length a screen accepts |
| Snapshot | Compiled campaign rules the bidder holds in memory (from Redis) |
| HFSS | Food high in fat, salt or sugar. Restricted placement |
| ASAI | Advertising Standards Authority for Ireland. Its code covers outdoor ads |
| Micros | Integer money units, 1/1,000,000 of a euro |
