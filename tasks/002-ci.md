# 002: CI runs every test suite on every pull request

## Why
Three agents will be merging work in parallel from now on. Without tests running automatically on every pull request, a break in one lane lands quietly and costs days to untangle. CI is also what the reviewer and Sam look at before merging.

## Context
- Test commands: `AGENTS.md`, section "Test commands"
- Versions in use: Python 3.12 (service Dockerfiles), Go 1.23 (`go.mod`), Next.js 15 (use Node 20)
- `apps/web` has no lockfile yet. `apps/advertiser` will appear in task 004

## Files you may touch
- `.github/**`
- `README.md`: the badge line only
- `apps/web/package-lock.json` (new file, generated by `npm install`)

## Scope
1. Add `.github/workflows/ci.yml`, triggered on `pull_request` and on `push` to `main`, with a concurrency group that cancels superseded runs.
2. Run separate jobs in parallel:
   - `campaign-api`: install requirements, `pytest`
   - `brain`: install requirements, `PYTHONPATH=../../packages/ruleset/python pytest`
   - `ruleset`: `pytest` in `packages/ruleset/python`
   - `agents`: install `agents/requirements.txt`, `python -m pytest agents/tests` from the repo root
   - `bidder`: `go vet ./...` and `go test ./...`
   - `ssp-simulator`: `go build ./...` and `go test ./...`
   - `ops-console`: `npm ci` (generate and commit the lockfile first) and `npm run build` in `apps/web`
   - `advertiser-app`: the same in `apps/advertiser`, skipped while that folder doesn't exist
3. Cache pip, Go modules and npm.
4. Add a CI status badge to the top of `README.md`.

## Out of scope
- Deploys and staging (Sprint 1)
- Branch protection settings. Sam turns on "require CI to pass" in GitHub after the first green run
- New linters beyond `go vet`

## Acceptance criteria
- [x] The workflow runs on this task's own pull request, and every job is green, OR each failing pre-existing test is listed under Open questions with its job and test name. Never disable or skip a test to get green
- [x] A full CI run takes under 10 minutes
- [x] No job needs secrets or a running database. If a test does, list it under Open questions
- [x] The README shows the badge
